В статье про коннекторы для России уже разбирали: у Claude есть каталог из 400+ официальных интеграций, но именно amoCRM и Bitrix24 - самые популярные CRM на российском рынке - в этот список не входят. Разница с тем же Notion или GitHub в том, что там подключение - на пару кликов, а здесь придётся строить мост самостоятельно. Хорошая новость - обе CRM отдают открытый REST API, и мост под силу собрать Claude Code.

Почему нет готового коннектора

Официальные коннекторы Claude делает либо сам сервис, либо Anthropic в партнёрстве с ним. amoCRM и Bitrix24 популярны в основном на русскоязычном рынке - глобальный спрос, под который в первую очередь считают такие партнёрства, здесь ниже, чем у условного Salesforce или HubSpot. Это не значит что подключение невозможно - значит только, что готового решения "в одно нажатие" ждать не приходится.

amoCRM: REST API v4 через OAuth2

amoCRM отдаёт REST API v4 (все запросы идут на /api/v4/...), авторизация - через OAuth2:

  1. Где брать доступ: в самом amoCRM - раздел amoMarket → «...» (три точки в правом верхнем углу, рядом с кнопкой Web Hooks) → «Создать интеграцию». Появятся два варианта: «Внешняя интеграция» и «Приватная интеграция».
  2. Выбирай «Внешняя интеграция» - она работает через обычные запросы к API amoCRM, авторизация и обработка данных происходят на твоей стороне (у Claude Code), загружать никакой сторонний JS-код не нужно. «Приватная интеграция» - для случаев, когда нужно встроить в интерфейс amoCRM чужой виджет с JS-кодом; для связки с Claude она не нужна и даёт лишний доступ.
  3. После создания внешней интеграции получаешь client_id и client_secret - это и есть ключи для следующего шага.
  4. Обмениваешь их на access_token и refresh_token через запрос к https://<поддомен>.amocrm.ru/oauth2/access_token
  5. access_token живёт ограниченное время, refresh_token используется чтобы получать новый без повторного входа

Дальше через API доступны контакты, сделки, кастомные поля и вебхуки на смену статуса сделки (можно подписать до 100 вебхуков на разные события). Это полноценный доступ - можно и читать, и создавать, и обновлять сущности CRM.

Пример из практики: воронка для лидов на amoCRM обычно строится на связке "контакт + сделка с кастомными полями" (источник, сегмент, статус) и pipeline из нескольких стадий (Новый → Прогрев → Квалифицирован → Оплата → Клиент). Webhook на смену стадии сделки - основной способ узнать, что лид продвинулся, без постоянного опроса API.

Bitrix24: быстрее через Incoming Webhook

У Bitrix24 два пути авторизации. Полноценный OAuth2 - для маркетплейс-приложений, с обновляемыми токенами, сложнее в настройке. Но для личного использования есть путь короче:

Incoming Webhook - в разделе «Разработчикам» → «Другое» → «Входящий вебхук» генерируется одна ссылка, включающая ID пользователя и секретный код. Эта ссылка не имеет срока действия и сразу даёт доступ к REST-методам с выбранными правами.

Это буквально настройка на 10 минут - без обмена токенами, без обновления access token по расписанию. Плата за простоту - ссылка не протухает сама, поэтому это фактически бессрочный пароль: если она попадёт не в те руки, доступ к CRM получит кто угодно. Хранить её нужно так же осторожно, как обычный пароль, и никогда не публиковать в коде или чатах.

Как собрать мост через Claude Code

Обе CRM - это обычные REST API поверх HTTP, а значит подключение сводится к тому же паттерну, что уже разбирали для Instagram и Google Таблиц:

  1. Заведи учётные данные (OAuth-токены amoCRM или webhook-ссылку Bitrix24) по шагам выше
  2. Сохрани их в переменных окружения - не в коде
  3. Попроси Claude Code написать небольшой скрипт под конкретную задачу: подтянуть список сделок, создать контакт по данным из другого источника, обновить статус лида
  4. Claude сам разберётся в формате запросов и ответов - обе CRM хорошо документированы, а паттерн "прочитать/записать через REST" ему знаком по десяткам похожих интеграций

Не обязательно строить сразу универсальный мост под все сценарии - начни с одной конкретной задачи (например, «когда в Notion у лида статус меняется на "оплачено", создавай сделку в amoCRM») и расширяй по необходимости.

Частые вопросы

Какой путь проще для старта - amoCRM или Bitrix24?
Bitrix24 через Incoming Webhook - там нет обмена токенами и обновления по расписанию, только один раз сгенерированная ссылка.
А если я работаю сразу с обеими CRM?
Ничего не мешает - мост под каждую собирается независимо, они не связаны друг с другом.
Нужно ли постоянно обновлять токен amoCRM вручную?
Нет, именно для этого нужен refresh_token - Claude Code может написать логику автоматического обновления access_token по истечении срока.
Опасно ли давать Claude Code доступ к CRM с реальными клиентскими данными?
Сам код выполняется на твоей машине или сервере, данные CRM не уходят третьим лицам через сам факт использования Claude для написания или запуска скрипта - но общие правила безопасности (не публиковать токены, не давать лишние права) действуют как обычно.
