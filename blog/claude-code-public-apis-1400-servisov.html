Как подключить Claude Code к 1400+ сервисам: база Public APIs и готовый промпт

Виктор Дачников 14 июля 2026 6 минут

🟡 Средний - нужна базовая настройка Claude Code и понимание основ

⚡ Не обязательно читать всю статью Сохрани статью в файл, открой папку с ним в Claude Code и напиши: «Проведи меня по этой инструкции шаг за шагом». Claude прочитает материал и поможет собрать интеграцию в твоём проекте. Если хочешь понять механику сам - читай дальше.

Claude Code может получать курсы валют, собирать новости, искать вакансии, проверять результаты матчей, обрабатывать документы и передавать данные в рабочие системы. Но доступа ко всем этим сервисам у него из коробки нет. Нужен API конкретного сервиса или готовое подключение через MCP.

Для поиска подходящих API есть бесплатный GitHub-каталог Public APIs. В нём собраны сотни сервисов по финансам, бизнесу, документам, разработке, аналитике, новостям, спорту и другим категориям. У каждой записи указано, нужна ли авторизация, работает ли соединение по HTTPS и можно ли обращаться к API прямо из браузера.

API и MCP: в чём разница

API - это способ, которым одна программа запрашивает данные или отправляет команды другой программе. Например, скрипт может запросить актуальный курс доллара, получить список вакансий или создать задачу в рабочей системе.

Claude Code в этом случае выступает как разработчик: читает документацию, пишет код интеграции, запускает тестовый запрос и встраивает результат в проект. Это удобно для конкретной автоматизации, отчёта, сайта или внутреннего инструмента.

MCP нужен, когда сервис должен стать постоянным рабочим инструментом Claude Code. После подключения MCP Claude может обращаться к Notion, GitHub, базам данных и другим системам через готовые команды. Официальная документация Anthropic описывает MCP как стандарт для подключения внешних инструментов, источников данных и API к Claude Code: документация Claude Code по MCP.

Простое правило такое: если нужно один раз собрать функцию или автоматизацию - начинай с API. Если Claude должен регулярно читать и менять данные в сервисе во время разных задач - ищи готовый MCP или собирай свой.

Как выбрать API в каталоге

Сначала формулируй не название технологии, а результат. Не «хочу какой-нибудь финансовый API», а «каждое утро получать курсы USD, EUR и CNY, сохранять историю и видеть изменение за неделю».

Затем открой Public APIs, найди нужную категорию и проверь пять вещей:

  1. Auth. No означает, что для базового запроса ключ обычно не нужен. apiKey требует регистрации и ключа. OAuth используется, когда сервис выдаёт доступ к аккаунту пользователя.
  2. HTTPS. Для нормального рабочего проекта выбирай HTTPS. Не передавай ключи и пользовательские данные по обычному HTTP.
  3. CORS. Это важно, если запрос будет идти прямо из браузера. Для серверного скрипта или бэкенда CORS обычно не мешает.
  4. Документация и лимиты. Проверь примеры запросов, ограничения бесплатного тарифа, частоту обновления данных и условия коммерческого использования.
  5. Стабильность. Каталог помогает найти сервис, но не гарантирует его качество. Перед внедрением Claude Code должен выполнить тестовый запрос и проверить ответ.

Бесплатный API не всегда означает «безлимитный и без регистрации». У одного сервиса может быть 100 запросов в день, у другого - ограничение по странам, а третий разрешает данные только для некоммерческих проектов.

Готовый промпт для Claude Code

Открой Claude Code в папке проекта и вставь этот промпт. Замени текст в квадратных скобках своей задачей.

text
Ты работаешь в текущей папке проекта.

Моя цель: [опиши результат простыми словами].
Пример: каждое утро получать курсы USD, EUR и CNY, сохранять историю в CSV и показывать изменение за 7 дней.

1. Открой каталог https://github.com/public-apis/public-apis и найди 3 подходящих API.
2. Сравни их по качеству документации, авторизации, HTTPS, лимитам, условиям использования и актуальности данных.
3. Покажи короткое сравнение и порекомендуй один вариант. До моего подтверждения ничего платного не подключай.
4. После выбора прочитай официальную документацию API и сделай один минимальный тестовый запрос.
5. Предложи простой план интеграции в текущий проект. Не меняй существующую архитектуру без необходимости.
6. Реализуй интеграцию, добавь обработку ошибок, таймаут и понятные логи.
7. Все ключи и токены храни только в переменных окружения. Не записывай секреты в код, README, CLAUDE.md и git. Создай .env.example без реальных значений.
8. Добавь тест или локальную фикстуру, чтобы основную логику можно было проверить без расходования лимита API.
9. Создай короткий README: как получить ключ, куда его положить, как запустить и какой результат ожидать.
10. Перед действиями, которые отправляют сообщения, меняют внешние данные, совершают платежи или публикуют контент, обязательно запроси моё подтверждение.

Если ссылка или документация недоступны, не выдумывай параметры API. Скажи, какую страницу или фрагмент документации мне нужно прислать.

Этот промпт заставляет Claude Code сначала выбрать сервис и проверить документацию, а уже потом писать интеграцию. Без этого он может взять первый попавшийся API, не заметить лимиты или опереться на устаревший пример.

Что можно собрать для работы

Вот несколько задач, с которых удобно начинать:

  • утренний отчёт по валютам, акциям или криптовалютам;
  • мониторинг новых вакансий по должности и городу;
  • сбор новостей по заданным темам с удалением дублей;
  • календарь праздников и событий для контент-плана;
  • проверка адресов, телефонов или email в CRM;
  • генерация документов и PDF из шаблонов;
  • получение спортивных результатов и расписаний;
  • поиск научных публикаций и формирование подборки;
  • запуск кода в песочнице или проверка технических заданий;
  • перенос данных между внутренним проектом и Airtable, Asana или другой рабочей системой.

Для первой попытки выбери задачу только на чтение данных. Когда результат стабильно работает, можно добавлять запись, отправку сообщений и другие действия, которые меняют внешние системы.

Безопасность: что нельзя отдавать интеграции

Ключ API даёт программе права на действия от твоего имени. Храни его в .env или системных переменных окружения, выдавай минимальные разрешения и начинай с тестового аккаунта. Если сервис поддерживает отдельный ключ только для чтения, используй его.

Не подключай неизвестный MCP-сервер только потому, что он нашёлся в поиске. Anthropic отдельно рекомендует проверять доверие к серверу: внешние данные могут содержать вредоносные инструкции для модели. Для корпоративных документов, клиентских баз и платежей лучше использовать официальные коннекторы или собственную небольшую интеграцию с понятным кодом.

Что сделать прямо сейчас

  1. Скопируй готовый промпт.
  2. Замени описание цели на одну рабочую задачу.
  3. Открой Claude Code в отдельной папке проекта.
  4. Попроси сначала сравнить три API, не писать код сразу.
  5. После выбора разреши собрать минимальную версию и проверь её на тестовых данных.

Когда разовая интеграция заработает, её можно превратить в постоянный инструмент: обернуть в MCP-сервер, подключить расписание или встроить в бизнес-процесс. Но начинать лучше с одного понятного запроса и измеримого результата.
