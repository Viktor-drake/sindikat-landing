Claudex Loop: план проверяет не тот, кто его писал

Нейросеть пишет план проекта уверенно. И так же уверенно сообщает, что план отличный.

Проверить себя она не может по простой причине: она его и написала. У неё нет второй точки зрения, есть только та, из которой план и родился. А дальше вы неделю строите по плану с дырой и переделываете.

Идея: проверяющий должен быть чужим

Claudex Loop разводит роли между разными провайдерами. Claude составляет план, модель OpenAI его атакует: ищет дыры, требует доказательств, не принимает отговорки. Круг за кругом, пока спорить не о чем.

Ключевое здесь не «две модели лучше одной», а то, что у проверяющего нет авторства. Ему нечего защищать.

Заметка

GitHub помечает лицензию как «прочее», и это сбивает с толку. В файле лежит обычный MIT, просто с дополнительным абзацем об атрибуции: часть скиллов заимствована у Matt Pocock, тоже под MIT. Никаких скрытых ограничений там нет.

Четыре фазы

  1. Разведка. Модель сначала читает существующий код и документацию, а для

нового проекта проверяет свои допущения. Вопросы идут после изучения, а не вместо него.

  1. Требования. План пишется сразу с критериями приёмки и командами, которыми

результат можно доказать. Не «сделать авторизацию», а «вот проверка, которая обязана пройти».

  1. Ревью плана. Второй провайдер читает план и код в режиме только чтения

и возвращает замечания с доказательствами. Ни одного файла он не трогает.

  1. Сборка и инспекция. Выбранный исполнитель строит, а противоположный

провайдер проверяет результат в свежей сессии. Кто строил, тот не проверяет.

Установка

Для Claude Code ставится как плагин, двумя командами:

code
/plugin marketplace add chaseai-yt/claudex-loop
/plugin install claudex-loop@claudex-loop

После установки открыть новую сессию, иначе команды не подхватятся.

Появляются четыре команды: claudex-route для быстрого выбора модели, claudex-loop для полного цикла, а также codex-review и codex-build, если нужно вызвать конкретную фазу руками.

Главное

Главное, о чём умалчивают ролики про этот инструмент: для полного цикла нужны обе стороны. То есть и Claude Code, и Codex CLI, с активными аккаунтами и входом в каждый. Если у вас есть только один доступ, кросс-провайдерная проверка не заработает, а именно она и есть вся суть.

Это не недостаток инструмента, это его устройство. Но считать стоимость надо заранее.

Ещё из требований: Python 3.10 или новее и чистый git-срез перед сборкой.

Где метод не поможет

  • Плохо поставленная задача. Две модели одинаково хорошо уйдут не туда, если

цель сформулирована размыто. Спор будет предметным, а направление неверным.

  • Мелкая правка. Гонять четырёхфазный цикл ради переименования функции

дороже, чем сделать её.

  • Вопросы вкуса. Где нет объективного критерия, ревью превращается в обмен

мнениями.

  • Экономия времени на старте. Цикл занимает время до первой строки кода.

Он окупается на проектах, где переделка стоит недели, и не окупается там, где переделка стоит час.

Частые вопросы

Это платно?
Сам инструмент бесплатный, MIT. Но полный цикл требует доступа к двум разным провайдерам, и вот это уже платно.
Можно ли обойтись одним Claude?
Часть команд заработает, но смысл теряется: проверять план будет тот же, кто его писал.
Данные уходят наружу?
План и релевантный код видят обе модели, то есть оба провайдера. Для закрытых проектов это надо учитывать отдельно.
Чем это отличается от «попроси Claude перепроверить»?
Отсутствием авторства у проверяющего и режимом только чтения на фазе ревью. Модель не может по-тихому поправить план вместо того, чтобы указать на дыру.
Заменяет ли это техлида?
Нет. Это ловит дыры в плане, а не решает, тот ли это план, который вам нужен.
