Google Таблицы и Docs через Claude: как настроить автоматическую работу с документами

Виктор Дачников 5 июля 2026 6 минут

Что ты получишь, прочитав эту статью

  • Поймёшь, почему прямое подключение Claude к Google Таблицам работает нестабильно
  • Разберёшься в рабочей схеме из двух частей: кто создаёт файлы, а кто их правит
  • Настроишь сервисный аккаунт один раз и больше не будешь об этом думать

Просишь Claude заполнить Google Таблицу - и получаешь ошибку доступа или файл не создаётся вообще. Проблема не в Claude, а в том, как устроены права Google. Разберём рабочую схему, которая закрывает это раз и навсегда.

Почему напрямую не работает

У сервисных аккаунтов Google (это специальный тип аккаунта для автоматизации, не привязанный к человеку) есть особенность: квота на создание файлов в Google Drive у них нулевая. Они физически не могут создать новый документ или таблицу с нуля - зато прекрасно читают и редактируют то, что им явно расшарили.

Отсюда и нестабильность: если пытаться делать всё через один и тот же механизм, часть операций будет падать без понятной причины.

Схема из двух частей

Создание - через личный Google-аккаунт (у него есть обычная квота Drive). Новый файл кладётся сразу в отдельную рабочую папку.

Правка и чтение содержимого - через сервисный аккаунт с доступом к Docs API и Sheets API. Он работает только с файлами, которые лежат в этой расшаренной папке или явно расшарены на его email лично.

Разделение ролей звучит сложно, но настраивается один раз, а дальше работает прозрачно - создал таблицу, сказал Claude что туда вписать, готово.

Как настроить: шаги

  1. Создать проект в Google Cloud Console (console.cloud.google.com) - бесплатно, нужен обычный Google-аккаунт.
  2. Включить два API в этом проекте: Google Docs API и Google Sheets API (раздел «Библиотека API»).
  3. Создать сервисный аккаунт (раздел IAM и администрирование → Сервисные аккаунты), скачать JSON-ключ - это файл с учётными данными, хранить его нужно как обычный пароль, не публиковать.
  4. Создать рабочую папку в личном Google Drive и расшарить её на email сервисного аккаунта (выглядит как имя@проект.iam.gserviceaccount.com) с правами Editor.
  5. Подключить Claude Code к этой связке - через MCP для создания файлов (работает под личным аккаунтом) и небольшой скрипт для чтения/записи содержимого (работает через JSON-ключ сервисного аккаунта).

После настройки создание нового файла делается через MCP-инструмент с указанием этой рабочей папки, а вся дальнейшая работа с содержимым - через API по id файла: прочитать диапазон, записать значения, дописать строки, найти и заменить текст.

Что это реально даёт

  • Таблица лидов - Claude сам вписывает новые записи по мере поступления, без ручного копипаста
  • Контент-дашборд - таблица с планом публикаций и промптами под каждую, которую Claude обновляет по ходу работы
  • Отчёты - вместо того чтобы собирать цифры руками, просишь Claude прочитать несколько таблиц и свести их в одну сводную

Работает и в обратную сторону - Claude может прочитать существующую таблицу и что-то с ней сделать: посчитать, найти закономерность, подготовить выгрузку.

Частые вопросы

Нужно ли уметь программировать, чтобы это настроить?
Сами шаги в Google Cloud Console делаются мышкой, без кода. Скрипт для работы с API можно попросить написать сам Claude Code - разобраться в готовом коде для этого не обязательно.
Это то же самое, что официальный коннектор Google Drive у Claude?
Официальный коннектор из каталога хорош для разового чтения файлов в диалоге. Эта схема даёт больше контроля для регулярной автоматизированной работы - когда нужно писать в конкретные диапазоны таблицы или собирать данные по расписанию.
Насколько это безопасно?
JSON-ключ сервисного аккаунта - это учётные данные, их нужно хранить так же осторожно, как пароль: не публиковать, не отправлять в чаты. Сам сервисный аккаунт видит только то, что ему явно расшарили - не весь твой Google Drive.
Что если файл не редактируется - ошибка доступа?
Почти всегда это значит, что файл не расшарен на сервисный аккаунт. Решение - расшарить сам файл или переместить его в папку, которая уже расшарена, с правами Editor.
