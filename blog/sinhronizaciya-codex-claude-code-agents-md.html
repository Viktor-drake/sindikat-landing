Как синхронизировать Codex и Claude Code через AGENTS.md

Виктор Дачников 10 июля 2026 6 минут

🟡 Средний уровень - работа с файлами проекта, без программирования

Что ты получишь, прочитав эту статью

  • Поймёшь, почему Codex и Claude Code по умолчанию не видят общий контекст одного проекта
  • Узнаешь два надёжных способа связать их без ручного дублирования правил
  • Настроишь связку так, чтобы не тратить время на синхронизацию при каждом изменении
  • Узнаешь про готовый набор шаблонов и инструмент для миграции старых файлов

Если работаешь одновременно с Codex и Claude Code над одним проектом, у каждого свой файл памяти о проекте: Codex читает AGENTS.md, Claude Code - CLAUDE.md. По умолчанию они не связаны - обновил инструкции для одного, второй об этом не узнает.

Почему это не работает "само собой"

AGENTS.md - открытый стандарт, который понимают 24+ инструмента (Codex, Cursor, Copilot, Windsurf, Cline и другие). Claude Code в этот список не входит - по официальному подтверждению Anthropic (май 2026), он не читает AGENTS.md нативно, только собственный формат CLAUDE.md. Запрос на нативную поддержку висит в их GitHub уже давно и набрал тысячи голосов, но обещаний по срокам нет.

Из-за этого при ручной синхронизации (просто просить один агент обновлять файл другого) есть риск дрейфа - Клод сегодня обновит, а через несколько сессий забудет, и файлы начнут расходиться.

Способ 1: симлинк - самый надёжный

Если оба файла должны быть буквально одним и тем же содержимым - делаешь симлинк, и CLAUDE.md физически становится ссылкой на AGENTS.md. Меняешь любой - меняются оба, дрейфа не будет никогда, потому что это один файл под двумя именами.

Mac/Linux:

bash
ln -s AGENTS.md CLAUDE.md

Важно для Windows: обычный ln -s тут не работает. Нужен mklink, и для симлинков (в отличие от хардлинков) может понадобиться либо запуск от администратора, либо включённый Режим разработчика в Windows. Если это неудобно - используй способ 2 ниже, он работает без особых прав на любой системе.

Способ 2: импорт - проще на Windows

Claude Code умеет подтягивать содержимое другого файла прямо в CLAUDE.md через @-импорт. Оставляешь AGENTS.md как основной файл с реальными инструкциями, а CLAUDE.md превращаешь в короткую ссылку на него:

code
@AGENTS.md

Это одна строка в файле CLAUDE.md. Claude Code при чтении подтягивает содержимое AGENTS.md как есть. Никаких особых прав, работает одинаково на Windows, Mac и Linux.

Готовый набор шаблонов и инструментов

Если начинаешь с нуля или хочешь привести существующие файлы в порядок - есть открытый набор agents-md-cookbook (community-проект, не от Anthropic, но проверенный и популярный):

  • Шаблоны - готовые AGENTS.md под 16+ стеков (TypeScript, Python, Next.js, Django и другие), можно просто скачать и adaptировать под себя
  • Линтер - проверяет файл на соответствие рабочим практикам, чтобы структура не расползалась со временем
  • Миграция - команда npx agents-md-migrate автоматически переносит существующий .cursorrules, CLAUDE.md или похожий файл в чистый AGENTS.md, не переписывать вручную

Рекомендация авторов набора: файл должен быть компактным (100-150 строк), с конкретными командами и реальными примерами кода в начале - это то, что агенты реально используют, а не общие описания проекта.

Как выбрать способ

  • Работаешь на Mac/Linux и хочешь максимальной надёжности - симлинк, способ 1
  • Работаешь на Windows или не хочешь разбираться с правами администратора - импорт @AGENTS.md в CLAUDE.md, способ 2
  • Начинаешь новый проект с нуля - возьми готовый шаблон из agents-md-cookbook под свой стек, дальше настрой связку любым из двух способов

Частые вопросы

Не проще ли просто дублировать правила в оба файла вручную?
Работает, пока не забудешь обновить один из них - а забудешь рано или поздно. Симлинк или импорт снимают эту заботу полностью.
Обязательно ли использовать оба инструмента - Codex и Claude Code?
Нет, это актуально только если реально работаешь с обоими на одном проекте. Если используешь только Claude Code - AGENTS.md тебе не нужен, работай напрямую с CLAUDE.md.
Планирует ли Anthropic добавить нативную поддержку AGENTS.md?
Запрос в их GitHub открыт и активно поддерживается сообществом, но официальных сроков или обещаний нет - пока рассчитывать стоит только на способы выше.
Что если у меня уже есть отдельные CLAUDE.md и AGENTS.md с разным содержимым?
Собери финальную версию правил в одном из них (или заново через шаблон), потом свяжи вторым способом - иначе один из файлов при связке перезапишет содержание другого.
